# خبراء هونداي وفورد — Workshop Manager Android

تطبيق Android عربي لإدارة ورشة السيارات، يعمل محلياً دون اتصال بالإنترنت ويدعم واجهة RTL وقاعدة بيانات SQLite داخل الهاتف.

## الحالة الحالية

تعمل هذه النسخة لإدارة العملاء والسيارات وأوامر الإصلاح والدفعات والمخزون والفواتير والصور. إصدار التطبيق الحالي هو 0.7.0.

## الميزات المتاحة

- لوحة رئيسية وإحصاءات عامة للحركة والدفعات والرصيد.
- إنشاء ملفات العملاء برقم هاتف أساسي فريد.
- إنشاء ملفات السيارات وربط كل سيارة بعميل، مع التحقق من VIN.
- إضافة صور السيارة وصور مؤشر الوقود عند التسجيل أو لاحقاً.
- إنشاء أوامر إصلاح وربطها بالعميل والسيارة وحفظ قراءة العداد عند الزيارة.
- إرفاق عدة صور لأمر الإصلاح عند الاستلام ومعاينتها من تفاصيل الأمر.
- تحديد أولوية الأمر والفني وتاريخ التسليم المتوقع.
- تسجيل الدفعات الجزئية والدفعة المقدمة وطرق الدفع والملاحظات.
- حساب إجمالي التكلفة والخصم والمبلغ المدفوع والمبلغ المتبقي.
- إضافة قطع الغيار للمخزون والبحث بالاسم والرقم والمورد والباركود.
- اقتراحات تلقائية للحقول مع تطبيع الأرقام العربية والهندية واللاتينية.
- استقبال البحث عن العملاء والسيارات عبر الهاتف واللوحة ورقم VIN.
- عرض تفاصيل العملاء والسيارات وأوامر الإصلاح وسجل الدفعات.
- إنشاء فاتورة عربية احترافية بتنسيق PDF متعدد الصفحات ومشاركتها بالطباعة أو تطبيقات المشاركة.
- صفحة تقرير مستقلة لكل سيارة تعرض سجل أوامر الإصلاح والإجماليات، مع تحرير نص مخصص للعميل وحفظه وطباعته أو مشاركته كـ PDF.
- تحرير أوامر الشغل الأصلية من سجل السيارة وإعادة إصدار أو طباعة فاتورة أي أمر.
- بدء تنفيذ أمر الإصلاح واعتماد إكماله مباشرة من تفاصيل الأمر، مع متابعة مهام الفنيين وحالة كل مهمة.
- إدارة المستخدمين والصلاحيات والنسخ الاحتياطي والاستعادة المحليين.
- ربط قطع المخزون بأوامر الإصلاح وخصم الكميات وتحديث تكلفة القطع تلقائياً.
- إدارة مهام الإصلاح والفنيين ومواعيد التنفيذ والتسليم والمراجعة.
- تسجيل الموافقات ومستندات التسليم والتوقيع الرقمي النصي المرتبطة بالأوامر.
- إنشاء ملصق QR لكل أمر إصلاح يحتوي هوية الأمر والعميل والسيارة.
- إدارة الفروع الأساسية وعرض سجل التدقيق للحركات المهمة.

## قرارات البيانات المطبقة

- العميل يُعرّف برقم الهاتف، ويمكن أن يمتلك عدة سيارات.
- لكل سيارة VIN فريد وسجل أوامر إصلاح مستقل.
- قراءة العداد تحفظ في أمر الإصلاح وتحدّث قراءة السيارة الحالية دون إنقاصها.
- لا يتم نقل ملكية السيارة تلقائياً عند تعارض الهاتف وVIN؛ يلزم إجراء نقل ملكية صريح في مرحلة لاحقة.
- الصور تحفظ داخل مساحة التطبيق ويربط كل منها بالسيارة أو أمر الإصلاح.
- تحفظ الدفعة المقدمة كسجل دفعة مرتبط بأمر الإصلاح عند إنشائه.

## البناء على GitHub

1. ارفع محتويات هذا المجلد إلى جذر المستودع `WorkshopManagerAndroid`.
2. تأكد من وجود الملف `.github/workflows/android.yml`.
3. من تبويب Actions شغّل `Build Workshop Manager APK` أو ادفع Commit إلى فرع `main`.
4. بعد نجاح البناء، افتح تشغيل Workflow وحمّل Artifact باسم `WorkshopManager-release-apk` أو `WorkshopManager-debug-apk`.

## اقتراحات إضافية للتطوير

1. **مسار أمر إصلاح كامل:** استقبال — تشخيص — موافقة العميل — قطع وعمالة — تأكيد التسليم — فاتورة.
2. **المواعيد والتذكيرات:** حجز موعد، تنبيه التسليم المتوقع، وتذكير بالدفعات المتأخرة.
3. **ملصقات ورمز QR:** ملصق للسيارة أو أمر الاستلام يحتوي رقم الأمر وعنوان سريع للتفاصيل.
4. **مستندات العميل:** إذن إصلاح، عقد تسليم، وطلب موافقة على القطع والتكاليف الإضافية.
5. **تأكد الجودة وتسليم السيارة:** صور قبل وبعد الإصلاح وتوقيع رقمي للعميل عند التسليم.
6. **تقارير متقدمة:** الأرباح اليومية والشهرية، الأعطال الأكثر تكراراً، أداء الفنيين وحركة المخزون.
7. **أرشفة ذكية للصور:** ضغط الصور وتنظيمها حسب السيارة والأمر والتاريخ مع بحث سريع.
8. **صلاحيات تشغيلية متقدمة:** مسؤول، رئيس ورشة، فني، وكاشير مع سجلات تدقيق منفصلة.
9. **دعم الفروع والمخازن:** مخزون وفواتير مستقلة لكل فرع ومالك مستخدمين مشترك.
10. **لوحة ويب اختيارية:** مزامنة سطح المكتب مع الهاتف لتسهيل المحاسبة والطباعة وإدارة المخزون.

## تنبيه

لا تضع بيانات عملاء حقيقية حساسة في هذه النسخة التجريبية قبل اكتمال تسجيل الدخول والصلاحيات والنسخ الاحتياطي والحماية المطلوبة.


## اقتراحات وتعديلات طلبها المستخدم 

١-عدم اظهار الصور في الفاتورة
٢-عند البحث عن سيارة يكتفي بكتابة الهاتف او رقم القعادة او رقم اللوحة
٣-امكانية ادخال اكثر من صورة بنفس الوقت وعرض الصور بعد الالتقاط مع امكانية الحذف اذا كانت غير واضحة مثلا
٤-عند تعبئة الحقول يجب ان لا يختفي الحقل الجاري تعديله تحت لوحة المفاتيح
 ٥-اضافة صفحة للاعدادات كاختيار اللغة وتحديد الوقت لتسجيل الخروج وتغيير بقية الاعدادات التي تقترحها وصفحة لاستعراض الصور
٦-تحسين واجهة التطبيق والصفحات والايقونات وجعلها بمظهر عصري 
٧-عمل صفحة للموارد البشرية (الفنيين, وموظفي الاستقبال ، وموظفي المخازن وقطع الغيار)
٨-هل يمكن اضافة وكيل ذكاء اصطناعي للتطبيق

## اقتراحات اضافية طلبها المستخدم

الرؤية المستقبلية للنظام

الهدف هو تطوير التطبيق من برنامج لإدارة ورشة واحدة إلى نظام ذكي ومتخصص لإدارة ورش صيانة السيارات بمختلف تخصصاتها، قابل للتخصيص حسب طبيعة كل ورشة، مع إمكانية تفعيل الوحدات التي يحتاجها صاحب الورشة فقط.

1. نظام متعدد التخصصات

يدعم النظام:

- الميكانيكا والمحركات وناقل الحركة.
- كهرباء السيارات والإلكترونيات.
- التكييف والتبريد.
- السمكرة والدهان.
- الإطارات والعفشة والفرامل.
- الفحص والتشخيص والصيانة الدورية.

يختار صاحب الورشة تخصصاته، ويحدد اسم المنشأة وشعارها وبيانات التواصل والعملة والضرائب وإعدادات الفواتير. ولا ترتبط هوية النظام بعلامة سيارات محددة.

2. دورة العمل المتكاملة

1. استقبال السيارة: البحث عن العميل والسيارة، تسجيل العداد والوقود، تصوير السيارة وتوثيق حالتها.
2. الفحص والتشخيص: تسجيل شكوى العميل والأعراض وظروف ظهورها ونتائج الاختبارات.
3. التقدير والموافقة: تحديد تكلفة القطع والأجور وتوثيق موافقة العميل.
4. التنفيذ: توزيع المهام على الفنيين ومتابعة العمل والقطع المستخدمة.
5. مراقبة الجودة: فحص ما بعد الإصلاح وتجربة السيارة وتسجيل النتائج.
6. التسليم والمحاسبة: إصدار الفاتورة وتسجيل الدفعات والمتبقي.
7. السجل التاريخي: حفظ جميع الزيارات والإصلاحات والقراءات والصور في ملف السيارة.

3. الذكاء التشغيلي والإداري

- تنبيهات أوامر الإصلاح المتأخرة والسيارات التي لم تُسلّم في موعدها.
- تنبيه انخفاض المخزون واقتراح إعادة الطلب.
- تحليل الإيرادات والمصروفات والربحية.
- متابعة إنتاجية الفنيين ومدة إنجاز الأعمال.
- تذكير العملاء بالصيانة الدورية والمواعيد والدفعات.
- لوحة مؤشرات تعرض حالة الورشة وأهم العمليات.

4. الملف الفني الذكي للسيارة

إنشاء سجل فني تراكمي لكل سيارة يشمل:

- الأعراض وشكوى العميل وظروف حدوث العطل.
- أكواد الأعطال DTC وبيانات Live Data.
- قراءات الفحص قبل الإصلاح وبعده.
- نتائج الاختبارات الكهربائية والميكانيكية.
- القطع التي تم فحصها أو استبدالها ونتائج الإجراءات.
- الحل النهائي وملاحظات الفني ومدى نجاح الإصلاح.

5. مساعد فني مدعوم بالذكاء الاصطناعي

مساعد اختياري يساعد الفني على:

- تحليل الأعراض والبيانات واقتراح مسارات فحص مرتبة.
- ربط الأعطال الحالية بحالات مشابهة في سجل الورشة.
- البحث في قاعدة المعرفة الفنية والحلول السابقة.
- تحليل بيانات Live Data التي يضيفها الفني.
- إعداد تقارير تشخيصية للفني والعميل.

يظل قرار التشخيص والإصلاح بيد الفني. ويجب أن يوضح المساعد أساس توصياته ودرجة عدم اليقين، وألا ينفذ تغييرات أو يعتمد إصلاحات تلقائياً دون موافقة المستخدم.

6. البنية المقترحة

- الهوية والإعدادات: بيانات المنشأة والفروع واللغة والعملة والضرائب والشعار والصلاحيات.
- الوحدات التشغيلية: العملاء والسيارات والاستقبال والإصلاح والمخزون والحسابات والموارد البشرية والتقارير.
- محرك التخصصات: نماذج وإعدادات تناسب الميكانيكا والكهرباء والتكييف والسمكرة وغيرها.
- محرك المعرفة والذكاء: السجل الفني وقاعدة المعرفة والتحليلات والمساعد الذكي.
- طبقة البيانات والمزامنة: قاعدة محلية تعمل دون إنترنت، مع مزامنة اختيارية عند توفر الاتصال.

7. خارطة الطريق

المرحلة الأولى — تثبيت الأساس

- إكمال ربط العملاء بالسيارات وسجل الزيارات ومنع التكرار.
- إكمال دورة الاستقبال والموافقة والتنفيذ والتسليم.
- مراجعة الدفعات والديون والمخزون والفواتير والصلاحيات.
- إكمال النسخ الاحتياطي والاستعادة واختبارهما.

المرحلة الثانية — تعدد أنواع الورش

- فصل هوية المنشأة عن اسم التطبيق.
- إضافة اختيار التخصصات والوحدات.
- توفير نماذج استقبال وأوامر عمل قابلة للتخصيص.
- دعم الفروع والعملات والضرائب.

المرحلة الثالثة — الذكاء التشغيلي

- مؤشرات الأداء والتنبيهات والتقارير.
- تطوير إدارة المخزون والتوريد.
- متابعة الجودة والمواعيد والصيانة الدورية.

المرحلة الرابعة — الذكاء الفني

- تطوير الملف الفني التراكمي للسيارة.
- بناء قاعدة معرفة للأعطال والاختبارات والحلول.
- إضافة المساعد التشخيصي تدريجياً وتحت مراجعة الفني.

المرحلة الخامسة — التوسع

- مزامنة آمنة بين الأجهزة والفروع.
- لوحة ويب للإدارة والتقارير والمحاسبة.
- التكامل مع الخدمات الخارجية عند الحاجة.

8. مبادئ حماية البيانات والاستقرار

- استمرار العمل محلياً عند انقطاع الإنترنت.
- تنفيذ أي تغيير في قاعدة البيانات عبر Migration واضح ومختبر.
- الحفاظ على بيانات المستخدمين والسجلات السابقة.
- اختبار الترقية على نسخة من قاعدة بيانات فعلية.
- نسخ احتياطي يشمل قاعدة البيانات والصور والمرفقات، مع اختبار الاستعادة.
- تطوير الميزات تدريجياً دون التأثير على الوظائف المستقرة.
- التمييز دائماً بين الميزات المنفذة والمختبرة والميزات المخطط لها.
